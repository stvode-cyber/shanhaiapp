## 一、纠正 AGENTS §11.6 快照的过时信息

| 快照原文 | 实际情况 | 影响 |
|----------|----------|------|
| "ReputationEngine（tier 全返回 EXCELLENT）" | **三层完整**：<60 RESTRICTED / <80 OBSERVED / ≥80 EXCELLENT；扣分明细（瞬移-18/超速-12/未知-10）、每日恢复+1 | 快照过时，原型已正确引用 |
| "ActivityEngine（ACTIVITIES[7] 但 startDay/duration 全 undefined）" | **7 个活动日期完整**（中元 2026-08-28~09-01 / 春节 2026-02-16~22 / 国庆 10-01~07 等），含 captureMul/expMul/incomeMul | 快照过时，运营配置就绪 |
| "ReputationEngine 浅接（仅引用）" | **GameState 深层调用**：canExploreLbs/lbsRareSpawnMul/reportIntegrity/reputationTier/ReputationEngine.tier 多处引用 | 引擎已深接，只是原型没做独立 tab |

**结论**：引擎覆盖矩阵实际覆盖率比快照标注的更高。需要更新 AGENTS §11.6。

## 三、设计缺漏清单（GDD vs 实现）

### D1. 原型缺独立活动 tab

| 项目 | 内容 |
|------|------|
| **现状** | ActivityEngine 完整实现（7 活动 + 乘性聚合 + 日期窗口判定），GameState 内部已缝接 captureMul/expMul/incomeMul 三条接缝。但**原型没有独立 tab 展示活动日历** |
| **GDD 依据** | 二十·待细化项 "Live Ops 日历：月度小版本 + 季度大版本" |
| **方案** | 活动日历 tab：列表展示 7 活动（名称/日期/乘子）+ 当前生效活动高亮 + 模拟日期切换 |
| **优先级** | 🟡 P2 |
| **改动量** | prototype/index.html + game.js 约 150 行 |

### D2. 原型缺信誉分层可视化

| 项目 | 内容 |
|------|------|
| **现状** | ReputationEngine 完整实现（三层 + 扣分 + 每日恢复），GameState 有 reportIntegrity/canExploreLbs/lbsRareSpawnMul。但原型 honor tab 里只浅引用 reputationLabel() |
| **GDD 依据** | 十六·公平与稳健 "信誉分：100 优秀 / 60–79 观察（稀有−30%）/ <60 限制（仅秘境）" |
| **方案** | honor tab 里加信誉分层仪表：当前分数条 + 阈值线（60/80）+ 观察层稀有标记 + 模拟扣分按钮 |
| **优先级** | 🟢 P3 |

### D3. 原型缺每日重置可视化

| 项目 | 内容 |
|------|------|
| **现状** | DailyResetEngine 完整实现 + GameState.maybeResetDaily 缝接。但原型没有跨天演示 |
| **GDD 依据** | 十六·防脚本 "单日收益封顶（疲劳值）" |
| **方案** | platform tab 加 "模拟跨天" 按钮，展示各重置项（疲劳/秘境次数/副本次数/商店购买/据点占领）的变化 |
| **优先级** | 🟢 P3 |
