# 用户行为偏好 · 山海妖志

> **新 AI 接手必读** —— 这是用户的行为习惯和期望，按此执行可减少摩擦、提高体感。
> 最后更新：2026-10-17

---

## 一、沟通风格

| 偏好 | 具体要求 |
|------|----------|
| **语言** | 中文 · 大白话 · 简单明了 |
| **回复格式** | 脑图代码块（`mermaid mindmap`） + 简洁正文 |
| **先对齐再动手** | 每次先汇报理解 → 用户确认 → 再写第一行代码 |
| **进度条** | 每轮必须有「目标 → 动作数 → 已完成 → 进度%」 |

## 二、操作习惯

| 偏好 | 具体要求 |
|------|----------|
| **只确认不操作** | 用户只做决定权，不手动操作细活。确认后全权交给 AI |
| **不喜欢过多操作** | 减少交互轮次，能一次干完的不分多次 |
| **质量优先不计成本** | 工作量大小不影响选择，只关注最强最稳定的办法 |
| **可验证优先** | 交付必须有客观证据（构建日志、测试输出、实际运行） |

## 三、记录与追踪

| 偏好 | 具体要求 |
|------|----------|
| **动作编号** | 每个动作带编号（#045、T30），出问题可追溯 |
| **台账同步** | 每轮必读必写工作台帐，动作流水/问题/决策/待办全更新 |
| **文件瘦身** | 减少上下文压力，分类归档，旧内容移入 archive/ |
| **新 AI 接手即懂** | 台帐+凭证+偏好三件套，新 AI 读 5 分钟可续 |

## 四、技术偏好

| 偏好 | 具体要求 |
|------|----------|
| **后端先思考再写** | 代码前先问：是不是一定要写？有没有更高效的办法？ |
| **联网学习** | 有问题就联网查、看开源项目、借 Skill |
| **借鉴三方资源** | 不为成本所限，只为质量 |
| **中文目录名硬坑** | Windows 上 emoji/中文路径导致 gradle JNI error → 必须 robocopy 到 C:\temp |

## 五、禁忌

| 红线 | 说明 |
|------|------|
| ❌ 谎报 | 做了多少说多少，没完成的不说完成 |
| ❌ 装懂 | 不会就说不会，别瞎给答案糊弄 |
| ❌ 空转等待 | 有阻断就标记并推进其余，别停在那等 |
