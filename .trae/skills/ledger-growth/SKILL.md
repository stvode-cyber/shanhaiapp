# 成长型台帐（Ledger Growth）

## 何时调用

- 新项目初始化工作台帐
- 同类问题重复出现（>3 次）需自动归类
- 台帐条目过多（>50）需合并精简
- AI 接手新会话/新电脑，需快速对齐项目状态
- 用户说"台帐升级""换电脑接手""AI 交接"

## 核心设计原则

1. **同类问题自动归类** — 用**根因簇（Root Cause Cluster, RCC）** 代替散点问题列表，同一类问题收敛到一个簇
2. **等级标记** — 每条子问题带修复等级 L1~L4，一眼看复杂度分布
3. **活跃度过滤** — 仪表盘只显示**未解决问题**；已解决自动归档
4. **双轨记录** — 台帐存摘要+索引，详细过程放每日日志（`.workbuddy/memory/YYYY-MM-DD.md`）

## 台帐结构模板（v2.0）

```
┌─ ① 仪表盘（Dashboard）—— 一眼看全局
│   ├─ 项目健康度（测试绿/红/覆盖率/构建状态）
│   ├─ 历史根因簇统计（次数+最高等级+状态）
│   └─ 活跃问题表（仅未解决 P#）
├─ ② 根因簇 RCC —— 同类问题归类，带等级和累计计数
├─ ③ 活跃问题 —— 独立于 RCC 的 P# 追踪
├─ ④ 动作流水 —— 最近 20 条，超过自动归档
├─ ⑤ 决策日志 —— D# 记录拍板的事（内容+理由+替代方案）
├─ ⑥ 任务池 —— T# 带状态标签（⬜🔄✅⏸🚫）
└─ ⑦ 本轮总汇 —— 每轮结束写，作为给用户的回复正文
```

## 根因簇等级速查

| 等级 | 定义 | 例子 |
|------|------|------|
| L1 | 小修（1-2 行） | import 缺失、拼写错 |
| L2 | 中等（3-5 行） | 类型签名不匹配、函数返回类型改 |
| L3 | 深层（逻辑重写） | 续行语法坑、嵌套函数推断失败 |
| L4 | 阻断（无法编译/测试） | 路径 JNI error、缺少 JDK/SDK |

## RCC 命名约定

```
RCC-01: 引用/包名/类名错
RCC-02: 类型签名漂移
RCC-03: 续行/语法坑
RCC-04: 测试期望值/数据漂移
RCC-05: 环境/路径/平台限制
RCC-06: 构建/依赖配置
```

> 新项目可从头建 RCC-01，按出现的问题类型自然生长。

## 动作流水格式

```
#编号 | 日期时间 | 动作描述（产出 + 文件） | 验证结果
```

> **⚠️ 编号时间对齐规则**：编号必须按真实时间单调递增。同一日期内可以有编号跳跃（比如上午干的编号小、下午深夜干的编号大但会话内编号分配相反），但最终归档时必须按**真实时间**重排，确保编号递增方向 = 时间推进方向。

超过 10 条 → 把最老的移到 `.workbuddy/archive/ledger_archive.md`，台帐只保留最近 10 条 + 索引。

## AI 交接要点（换电脑/新 AI 接手）

台帐必须包含以下 **"AI 接手三件套"**，缺一即补：

1. **当前可验证状态** — 哪些构建绿、哪些测试绿、哪些产物已出包（仪表盘）
2. **活跃阻断** — 所有 🚫 和 🟥 P#，以及为什么阻断（RCC-05/P29 类的平台限制要注明）
3. **下一个明确目标** — 任务池里最高优先级的未完成项 + 推进路径

接手 AI 的工作循环 = 看台帐 → 评估 → 选定下一步 → 实现 → 验证 → 记台帐 → 循环。

## 迁移旧台帐

如果现有台帐是散点结构（非 RCC）：
1. 把所有问题按**根因类型**分组（不是按时间或文件）
2. 每组编号为 RCC-01/RCC-02/... 并标记累计次数
3. 已解决的直接归档，只留未解决的进仪表盘活跃表
4. 决策和任务池补状态标签
